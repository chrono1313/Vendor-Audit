Vendor Audit

A passive check of a domain's security and best-practice posture.

How this is meant to be used

Vendor Audit is a due-diligence tool. Run it on a vendor's domain before purchasing a product or service to get a quick, evidence-based read on how their configuration aligns with current best practices. A weak score isn't a deal-breaker on its own, but it's a useful conversation starter and a data point alongside everything else you're evaluating.

Please share the report with the vendor. Every section cites the RFC, W3C spec, OWASP guidance, or CA/Browser Forum baseline it's measured against — so the report reads as feedback, not as an accusation. Most vendors appreciate a heads-up they can act on; the report gives them one in a form they can take straight to the people who can address it. When more than one prospect shares these reports with the same vendor, they're more likely to prioritize the issues raised.

What this checks

The audit covers SPF, DMARC, DKIM, MX, MTA-STS, TLS-RPT, DNSSEC, CAA, RPKI, IPv6, TLS configuration, HSTS, HTTP/2 and HTTP/3 support, security headers, cookie attributes, EOL libraries and operating systems, and more — about 60 scored checks against published standards.

This service is passive: it reads what the domain voluntarily publishes (DNS, HTTPS GET, public APIs). It does not port-scan, brute-force, or probe for vulnerabilities. The full source is on GitHub; a CLI is also available for batch use, deep-mode checks, SSL Labs integration, and bulk audits.
